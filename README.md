# בוט ידע ארגוני – מוסד הלימודים "נתיבות"

בוט שעונה לתלמידות ולהורים על שאלות לגבי המוסד: תקנון, היעדרויות, בחינות, לוח חופשות ושכר לימוד.
הבוט עונה **רק** מתוך המסמכים שבתיקיית `data`. אם המידע לא קיים במסמכים, הוא עונה שלא מצא מידע ומפנה למזכירות.

**טכנולוגיות:** Python · LlamaIndex · ChromaDB · OpenAI API · Streamlit

---

## התקנה והרצה

**הדרך המהירה (Windows):** ליצור קובץ `.env` עם המפתח, ללחוץ לחיצה כפולה על `setup.bat` (מתקין Python 3.12 אם חסר, יוצר סביבה וירטואלית, מתקין ספריות ובונה את האינדקס), ואז על `run.bat`.

**ידנית:**

```bash
# 1. סביבה וירטואלית
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Mac / Linux

# 2. התקנת ספריות
pip install -r requirements.txt

# 3. להעתיק את .env.example ל-.env ולמלא:
#    OPENAI_API_KEY=sk-...
#    ADMIN_PASSWORD=סיסמה-לבחירתך

# 4. יצירת הווקטורים מהמסמכים (פעם אחת, ובכל שינוי במסמכים)
python ingest.py

# 5. הרצת הממשק
streamlit run app.py
```

## מבנה הפרויקט

| קובץ | תפקיד |
|---|---|
| `config.py` | כל ההגדרות ונקודות ההחלטה במקום אחד |
| `models.py` | אתחול מודל הווקטורים ומודל התשובה ב-LlamaIndex |
| `ingest.py` | טעינת מסמכים → חלוקה ל-chunks → יצירת וקטורים → שמירה ב-ChromaDB |
| `rag.py` | הרחבת שאלה → חיפוש ב-ChromaDB → יצירת תשובה מהמסמכים בלבד |
| `app.py` | ממשק צ'אט ב-Streamlit (מציג רק את התשובה) |
| `data/` | המסמכים הארגוניים (‏md, ‏txt, ‏pdf, ‏docx) |

## נקודות ההחלטה

| # | החלטה | מה בחרתי | נימוק |
|---|---|---|---|
| 1 | Vector DB | **ChromaDB** (מקומי, `PersistentClient`) | נלמד בכיתה, לא צריך שרת חיצוני, חינמי, ושומר את הנתונים בתיקייה מקומית |
| 2 | ספרייה | **LlamaIndex** | דרישת התרגיל. מספקת טעינת מסמכים, חלוקה, וחיבור מוכן ל-Chroma ול-OpenAI |
| 3 | אופן חלוקת הידע | **לפי טוקנים**: ‏`SentenceSplitter`, ‏512 טוקנים | חלוקה לפי משמעות (semantic) יקרה, כי היא דורשת וקטור לכל משפט. חלוקה לפי טוקנים מדויקת יותר מחלוקה לפי מילים (בעברית מילה יכולה להיות כמה טוקנים), ו-`SentenceSplitter` לא חותך באמצע משפט |
| 4 | חפיפה בין chunks | **כן, 64 טוקנים** (כ-12%) | כשמידע נחתך בין שני chunks, החפיפה שומרת את ההקשר בשניהם |
| 5 | ספק API | **OpenAI** (בתשלום) | מחירים נמוכים, וחיבור מוכן ב-LlamaIndex |
| 6 | Top K | **4** | המסמכים קצרים וממוקדים. 4 קטעים נותנים מספיק הקשר בלי להכניס מידע לא רלוונטי שמבלבל את המודל ומייקר את הקריאה |
| 7 | מודלים | וקטורים: **text-embedding-3-small**; תשובה: **gpt-4.1-mini** | מודל ההטמעה הזול של OpenAI (0.02$ למיליון טוקנים). ‏gpt-4.1-mini מהיר, זול (0.40$ / 1.60$ למיליון טוקני קלט / פלט) ומבין עברית היטב. ‏temperature=0 לתשובות עקביות |
| 8 | הרחבת שאלה | **כן, רק לשאלות קצרות** (פחות מ-6 מילים) | שאלה כמו "מועד ב'?" מחזירה תוצאות חלשות. הרחבה לכל שאלה הייתה מוסיפה קריאת API ועיכוב גם כשאין בה צורך. החיפוש נעשה עם השאלה המורחבת, אבל התשובה נוצרת לשאלה המקורית. אפשר לכבות בממשק |
| 9 | צורת חיפוש | **חיפוש וקטורי לפי דמיון cosine** | מודלים של OpenAI מותאמים ל-cosine, בעוד שברירת המחדל של Chroma היא L2. הגדרתי `hnsw:space = cosine` ביצירת האוסף |

### איך הבוט נשאר צמוד למידע הארגוני
- הנחיית מערכת שמחייבת לענות רק מתוך הקטעים, ואחרת להחזיר תשובה קבועה ("לא מצאתי מידע...").
- `temperature=0`.

### הרשאות: מי יכולה להוסיף מסמכים
העלאת מסמכים ובנייה מחדש של האינדקס זמינות בממשק רק אחרי הקלדת סיסמת מנהלת בסרגל הצד.
- הסיסמה נשמרת בקובץ `.env` (`ADMIN_PASSWORD`) ולא בקוד.
- אם לא מוגדרת סיסמה, אפשרות ההעלאה לא מוצגת לאף אחד.
- הבדיקה נעשית עם `hmac.compare_digest`, שמשווה בזמן קבוע.
- שם קובץ שהועלה עובר `os.path.basename`, כדי שלא אפשר יהיה לשמור קובץ מחוץ לתיקיית `data`.

הסיבה: מי שמעלה מסמך יכולה לשנות את התשובות של הבוט, וכל בנייה מחדש עולה כסף בחשבון ה-API.

## 3 בעיות שנתקלתי בהן ואיך פתרתי

### בעיה 1: התקנת הספריות נכשלה בבניית pyyaml
**מה קרה:** בהרצת `pip install -r requirements.txt` ההתקנה נעצרה עם השגיאה:
`ERROR: Failed to build 'pyyaml' when getting requirements to build wheel`

**הסיבה:** במחשב הייתה מותקנת גרסת ניסיון של פייתון (Python 3.15.0a7). לגרסה שעוד לא יצאה רשמית אין לספריות גרסאות מוכנות (wheels), ולכן pip ניסה לבנות את pyyaml מקוד המקור ונכשל.

**הפתרון:** התקנתי לצד הגרסה הקיימת את Python 3.12, שהיא גרסה יציבה שכל הספריות תומכות בה. יצרתי סביבה וירטואלית שמבוססת עליה (`py -3.12 -m venv venv`) והתקנתי את הספריות בתוכה. כך הפרויקט רץ על 3.12 בלי לשנות את הגרסה הכללית במחשב.

### בעיה 2: תצוגת הממשק ב-Streamlit לא התאימה למשתמשות
**מה קרה:** בגרסה הראשונה של הממשק היו שתי בעיות:
1. הטקסט בעברית, השאלות והתשובות, הוצג מיושר לשמאל ובכיוון שמאל-לימין, כך שהיה קשה לקרוא אותו.
2. מתחת לכל תשובה הוצגו "פרטי החיפוש": השאלה המורחבת, שמות הקבצים, ציוני הדמיון וקטעים מהמסמכים. בנוסף, המודל ציין בסוף כל תשובה את שם הקובץ שממנו נלקח המידע.

**הסיבה:**
1. ‏Streamlit בנויה לשפות שנכתבות משמאל לימין, ואין בה הגדרה מובנית לעברית.
2. את פרטי החיפוש הוספתי בהתחלה כדי לבדוק שהבוט שולף את הקטעים הנכונים. זה מידע טכני שמתאים לפיתוח, אבל מבלבל תלמידה או הורה שרוצים רק תשובה.

**הפתרון:**
1. הוספתי לממשק CSS שמגדיר `direction: rtl` ו-`text-align: right` לכל רכיבי הטקסט.
2. הסרתי מהממשק את פרטי החיפוש ואת המתג להצגתם. בהנחיה למודל החלפתי את הבקשה לציין מקור בהוראה מפורשת לא לציין שמות קבצים או מקורות. כך המשתמשת רואה רק תשובה נקייה.

### בעיה 3: כל משתמשת יכלה להוסיף מסמכים ולשנות את התשובות של הבוט
**מה קרה:** בגרסה הראשונה של הממשק הופיעה בסרגל הצד אפשרות להעלות מסמכים ולבנות מחדש את האינדקס, וכל מי שפתחה את הבוט יכלה להשתמש בה.

**הסיבה:** הממשק לא הבחין בין משתמשת רגילה (תלמידה או הורה) לבין מנהלת. כך כל אחת יכלה להעלות מסמך עם מידע שגוי, והבוט היה עונה ממנו כאילו זה מידע רשמי של המוסד. בנוסף, כל בנייה מחדש של האינדקס עולה כסף בחשבון ה-API.

**הפתרון:** הוספתי כניסת מנהלת עם סיסמה בסרגל הצד. רק אחרי הקלדת הסיסמה הנכונה מוצגות אפשרויות העלאת המסמכים וההגדרות. הסיסמה נשמרת בקובץ `.env` ולא בקוד, ואם לא הוגדרה סיסמה, אפשרות ההעלאה לא מוצגת לאף אחד. בנוסף, שם הקובץ שמועלה עובר `os.path.basename`, כדי שאי אפשר יהיה לשמור קובץ מחוץ לתיקיית `data`.
